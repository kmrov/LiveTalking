# SillyTavern в LiveTalking Studio

## Цель

Добавить Виктора Петровича как отдельную личность SillyTavern и дать Studio режим разговора с ней через существующие WebRTC, WHIP, ASR, TTS и MP4. Диалоги SillyTavern отделены от Persona. Текст характера берётся из проверенного `~/persona/src/persona/persona.md`, но инструкции о `save_memory` и `search_memory` исключаются: эти инструменты в SillyTavern не подключены.

## Границы

Studio запускает или использует локальный SillyTavern на `127.0.0.1:8001`, не меняя его исходники. В нём создаётся стандартная карточка Виктора Петровича. Для Studio используется отдельный адаптер на `127.0.0.1:8002`, который говорит с SillyTavern по его существующему HTTP API и предоставляет совместимый с Persona API для LiveTalking. Адаптер вызывает `/api/backends/chat-completions/generate` с потоковым ответом, читает карточку через `/api/characters/get`, а разговоры хранит через `/api/characters/chats` и `/api/chats/get|save`. Запросы к SillyTavern проходят с cookie и CSRF-токеном. Зависимости SillyTavern устанавливаются отдельно; Studio их не устанавливает при запуске.

## Генерация

Адаптер собирает `messages` из описания карточки, последних реплик выбранного чата и новой реплики. Он использует текущий Yandex AI Studio key/folder Studio и модель Qwen3.6 35B через SillyTavern Custom Chat Completion backend. Ключ не записывается в профиль или карточку. Поток токенов преобразуется в существующие события `delta`/`done`; LiveTalking продолжает дробить его на фразы и отправлять в TTS. Повтор с тем же `request_id` не создаёт вторую реплику. Ошибочный ответ не сохраняется. Обрыв после сохранения читается из чата и воспроизводится при повторе.

Это использование серверного API SillyTavern и его стандартного формата чатов. Prompt Manager, worldbooks, браузерные расширения и выбранный в веб-интерфейсе провайдер не исполняются для реплик Studio. Они остаются доступны при отдельном разговоре в веб-интерфейсе. Синхронизацию личной памяти Persona и SillyTavern эта версия не выполняет.

## Studio и жизненный цикл

Профиль получает режим `sillytavern` и локальный URL SillyTavern. Persona URL и настройки сохраняются при переключении обратно. Studio проверяет Node.js, `server.js`, `node_modules`, ключ/папку Yandex, доступность ST API и доступность собственного адаптера. При Start запускает только необходимые процессы; Stop завершает только принадлежащие Studio процессы. Занятый чужим сервисом порт или несовместимый SillyTavern даёт явную ошибку. Новый режим показывает разговоры и потоковый ответ, скрывает Persona memory/documents. Смена разговора во время записи остаётся запрещена.

## Проверка

Тесты клиента охватывают cookie/CSRF, карточку, чтение/запись стандартного чата и SSE генерации. Тесты адаптера охватывают повтор `request_id`, ошибку модели и соответствие ответного потока. Тесты профиля и супервизора охватывают существующие профили, запуск/Stop и чужие процессы. После сборки выполняются `npm test`, `npm run build`, доступные smoke и ручной короткий запрос к локальному SillyTavern без GPU.
