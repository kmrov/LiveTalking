# Ditto and SoulX FlashHead Lite in Studio

The user wants to try Ditto and SoulX as alternatives to MuseTalk, using the current character and existing Qwen/Persona conversation and WebRTC/WHIP output. Success means selectable image avatars, real model inference, synchronized audio/video, interruption, and explicit installation errors. Quality and speed on the RTX 3090 must be measured, not inferred from upstream demonstrations.

## Architecture

Add model IDs `ditto` and `soulx` (SoulX FlashHead Lite). Each uses a PNG/JPEG reference copied into the existing avatar library. Keep environments separate: model-specific workers run with the interpreter and repository configured in `models/<model>/runtime.json`. JSON configuration contains `python`, `root`, and `weights` absolute paths (SoulX additionally `wav2vec`). No dependencies are installed at normal application startup.

The LiveTalking server owns a persistent subprocess for its generative session. Protocol on stdin/stdout is JSON Lines: init with source, render with float32 mono 16 kHz base64 audio, reset, close. Logs go to stderr. Ready declares fixed `chunk_frames` at 25 fps. Each render yields exactly that many RGB frames, transported as base64 JPEG messages followed by done. Errors fail explicitly. Models remain loaded between chunks; reset clears motion/audio history. Any necessary internal context must not shift the returned audio alignment.

A shared adapter queues TTS audio with its metadata, groups it according to the engine's chunk size, and publishes matching video/audio through existing output and recording APIs. Idle can use a still reference; active speech is always generated by the selected engine. Interrupt discards both queued and in-flight speech and starts a fresh model motion sequence. Backpressure bounds buffered video; stop/session close terminates owned workers, including on exceptions. Only 25 fps and one simultaneous generative session are supported initially.

Measured Ditto PyTorch inference on the local RTX 3090 is below real time. Default `buffered_playback: true` prepares an entire TTS utterance in a bounded disk-backed temporary buffer before normal-rate playback; it avoids injecting artificial silence between slow model chunks. `buffered_playback: false` retains streaming for faster configurations; the installed SoulX runtime and its setup script select this mode after measured 36.6 fps on the RTX 3090. An end marker or 0.5s input idle closes a buffered utterance; interrupts discard it. This mode adds response latency and is exposed as an experimental integration in the UI/docs.

## Studio

Create image avatars for either engine without MuseTalk face detection or GPU preparation. Store a normalized reference in `full_imgs/00000000.png`, an engine marker, a thumbnail, and the preserved source using existing jobs/publishing. Library identifies the declared engine and rejects conflicting metadata. Prerequisites check runtime installation and weights and provide a concrete setup action. Existing Qwen weight downloading must still work for these engines. English UI, Russian README.

## Setup and verification

Provide repeatable model setup instructions/tooling with pinned upstream revisions and isolated environments. Download only the required variant. Create separate trial avatars from the existing texture. Verify worker protocol and cancellation using fixtures; run existing Python desktop and npm tests/build/smokes where possible. Run a short real GPU sample for each engine, report wall time and memory, and inspect output before claiming quality. Projection pose stability remains a separate physical check.
