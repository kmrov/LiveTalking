# Studio avatar library: итог проверки

Реализованы создание MuseTalk v15 из фото/видео, Wav2Lip из видео, сохранённая библиотека с именами/миниатюрами/поиском/переименованием, выбор существующего Ultralight, собственная копия исходника, прогресс/отмена/повтор/восстановление. Голос остаётся настройкой профиля. Публикация не перезаписывает существующие каталоги; выбор сохраняет модель и ID в профиле версии 1.

Независимый read-only reviewer проверил диапазон `b23a046..6504919`: Critical — 0, Important — 7, Minor — 1; исключённых из оценки сценариев нет. Все Important исправлены одним проходом с наблюдавшимися RED→GREEN регрессиями:

1. Недоступный сохранённый checkout открывает окно настроек с отдельной ошибкой библиотеки.
2. Отказ записи журнала не препятствует остановке собственной группы worker.
3. Внешний LiveTalking принимается только при совместимых модели, каноническом checkout и мозге; его процесс сохраняется.
4. Первое обращение к каждому checkout восстанавливает оставшиеся задания; действующая собственная задача сохраняется.
5. События связываются с канонической библиотекой, включая root через ссылку и завершающий `/`.
6. Миниатюры обрабатываются последовательно вне Electron main, с ограничением 32 Мп, 1 GiB адресного пространства и 30 s. FFmpeg preview ограничен одним потоком. Непригодное превью оставляет готовую карточку без картинки.
7. Fingerprint исходника передаётся worker; повторная проверка после остановки сервисов и проверки открытого файла до/после копирования выявляет замену/изменение. Непроверенная копия не публикуется.

Проверки после исправлений:

- JS: 94/94 именованных теста; `npm test` — 25 файловых suites.
- Python: 25/25 desktop-тестов и 8/8 launcher-тестов.
- Renderer build — успешно.
- Electron smoke — пять сценариев: обычный запуск/речь, повреждённый профиль, недоступный checkout, весь сценарий библиотеки и потоковые ответы «Бати».
- Smoke библиотеки включает создание до настройки голоса, закрытие/возврат фокуса, источник удалён до публикации и после ошибки, повтор, миниатюры/выбор после перезапуска, поиск/переименование, смену модели после записи во время ответа «Бати», сохранение истории, отмену и закрытие без orphan, восстановление после контролируемого аварийного выхода. Root задан через символическую ссылку с `/`.
- Реальные Pillow preview/нормализация фото, Unicode-path FFmpeg video → 25 fps/3 декодированных кадра и preview в ограниченном subprocess — успешно.

Практическая GPU-проверка ограничена read-only диагностикой: RTX 3090, CUDA и зависимости доступны, основные веса MuseTalk найдены, но локальный S3FD отсутствует. Реальное создание MuseTalk photo/video, Wav2Lip video и WebRTC/озвучивание этих новых аватаров не проверены. Модели не скачивались; ранее работавшие сервисы не останавливались.

Принятые решения:

- В Node 26 дополнительно использовать `--test-isolation=none`, поскольку обычный запуск отображает только файловые suites. Обычный `npm test` также выполнен. Цена ошибки: дополнительный режим может не воспроизвести особенности изоляции процессов.
- Исправить также динамический импорт packaged MuseTalk face detector: исправления импорта preprocessing было недостаточно. Цена ошибки: сторонний вызывающий код, полагающийся на отдельный alias `face_detection`, может потребовать обновления. Импорт репозиторного пакета проверен регрессией.

Отложено одно Minor: независимый `Buffer.toString()` на chunks stdout/stderr может искажать разделённые байты кириллицы в сообщениях и журнале. На владение процессом, модель, путь и состояние протокола это не влияет; нужен потоковый UTF-8 decoder и отдельная регрессия.
