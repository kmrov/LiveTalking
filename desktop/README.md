# LiveTalking Studio — Linux

Electron-интерфейс для локального LiveTalking. Приложение проверяет окружение, запускает Qwen ASR/TTS, LiveTalking и «Батю», показывает аватара по WebRTC, озвучивает потоковые ответы, распознаёт микрофон, прерывает речь и сохраняет MP4. «Батя» ведёт постоянные разговоры и память в PostgreSQL.

## Запуск

Нужны Linux с графической сессией и Node.js 22 или новее:

```bash
cd LiveTalking/desktop
npm ci
npm start
```

Если npm запретил установочные скрипты зависимостей и Electron сообщает, что не установлен, один раз выполните:

```bash
node node_modules/electron/install.js
```

Приложение само находит родительский checkout LiveTalking. Для установленного приложения поиск рассчитан на папку `LiveTalking` рядом с исполняемым файлом; для AppImage используется расположение самого AppImage, а не временный mount. Выбор каталога вручную нужен только при другой структуре папок.

## Первый запуск

Мастер предлагает `.venv/bin/python` внутри LiveTalking, vLLM из соседнего `.venv` и vLLM-Omni из соседнего `.venv-omni`. Пути можно изменить. Python, CUDA и веса приложение не устанавливает.

Пример существующей структуры:

```text
live/
├── LiveTalking/
│   ├── desktop/
│   ├── .venv/bin/python
│   ├── models/
│   └── data/avatars/
├── .venv/bin/vllm
├── .venv-omni/bin/vllm
├── .hf-cache-qwen/hub/
└── cloning/
    ├── voice_reference_name.wav
    └── voice_reference_name.txt
```

Для Qwen нужны подготовленные `Qwen/Qwen3-ASR-0.6B` и `Qwen/Qwen3-TTS-12Hz-1.7B-Base`, vLLM и vLLM-Omni. Подготовьте отдельные окружения по [инструкции Qwen3-ASR](https://github.com/QwenLM/Qwen3-ASR#deployment-with-vllm) и [инструкции vLLM-Omni](https://docs.vllm.ai/projects/vllm-omni/en/latest/getting_started/quickstart/). Мастер ищет кеш моделей в `HF_HOME`, соседнем `.hf-cache-qwen` и стандартном Hugging Face cache; проверяет файлы конфигурации, веса и все части разделённых весов. Также проверяются веса выбранной модели аватара.

Готовый WAV и одноимённый TXT находятся автоматически в `LiveTalking/data/voices`, `LiveTalking/voices` или соседней папке `cloning`. В `cloning` используются файлы `voice_reference_*.wav`. Предлагается самый свежий образец; если их несколько, можно выбрать другой из списка. Расшифровка должна точно соответствовать записи. В этой версии профиль ссылается на исходный WAV: сохраняйте его на месте.

В блоке **Аватар** нажмите **Выбрать** для готового аватара или **Создать** для фото/видео. Модель определяется выбранной карточкой; вводить ID вручную не требуется. Для локального аватара нужен NVIDIA GPU даже при внешних ASR/TTS серверах. Внешний режим проверяет модели через `/v1/models` и не запускает vLLM.

Нажмите **Проверить**, исправьте указанные проблемы, затем **Запустить**. При запуске профиль сохраняется автоматически. После первого успешного запуска он открывается и запускается сам, если включено «Запускать при открытии». **Остановить** и закрытие приложения завершают только его собственные процессы. Совместимые сервисы, которые уже работали до запуска приложения, остаются работать.

## Создание и библиотека аватаров

**Создать** открывает выбор исходника, имя и модель. MuseTalk v15 поддерживает PNG/JPEG и видео MP4/MOV/MKV/AVI; Wav2Lip — видео этих форматов. Подготовленные Ultralight доступны для выбора. Для фото используйте хорошо видимое лицо; видео нормализуется до 25 кадров/с без звука. Дополнительные параметры кропа и маски находятся в раскрывающемся блоке.

Первого аватара можно создать до настройки голоса, ASR/TTS и «Бати». **Проверить подготовку** проверяет выбранное Python-окружение, CUDA, локальные веса и место на диске. Для MuseTalk нужны VAE, UNet v15, face parsing и детектор S3FD; для подготовки Wav2Lip — S3FD. Детектор ищется в `avatars/<model>/…/detection/sfd/s3fd.pth` или Torch Hub `checkpoints/s3fd-619a316812.pth`. Зависимости и модели автоматически не устанавливаются и не скачиваются.

Подготовка показывает этап и прогресс. Закрытие диалога, в том числе Escape, оставляет её работать; кнопка **Подготовка** возвращает к текущей задаче. **Отменить** завершает её собственный процесс. После ошибки/прерывания **Повторить** использует сохранённую копию исходника, если копирование успело завершиться. Закрытие Studio отменяет текущую задачу; после аварийного выхода состояние восстанавливается как прерванное. Готовый результат публикуется только после проверки всех кадров.

При работающем профиле действия подписаны **Остановить и создать** или **Остановить и выбрать**. Сначала завершите запись MP4. После выбора или подготовки сервисы запускаются отдельной кнопкой **Запустить**. Смена аватара закрывает WebRTC и поток событий; «Батя» сохраняет незавершённый ответ, который доступен в истории того же разговора.

Библиотека показывает существующие и созданные аватары по имени и миниатюре. Есть поиск и переименование без изменения ID; одинаковые имена допустимы. Неполные/повреждённые каталоги показываются с причиной и недоступны для выбора. Выбор сохраняется в текущем профиле вместе с настройками голоса.

Готовые аватары остаются в `LiveTalking/data/avatars/<id>`. Созданный аватар хранит `studio-avatar.json`, миниатюру и собственный исходник в `source/input.<extension>`: первоначальный файл после успеха можно удалить. Рабочие задания, копии для повтора и журнал находятся в `data/.studio-avatar-work/<jobId>` и не отображаются карточками. Голос настраивается отдельно; его исходный WAV пока нужно сохранять на месте.

## Разговор

1. Дождитесь состояния «Работает» и нажмите **Подключить WebRTC**.
2. Введите текст и выберите «Чат с LLM» или «Озвучить текст». В режиме «Батя» все запросы `chat` к LiveTalking, включая внешние клиенты, проходят через него. В прямом режиме LLM использует настройки LiveTalking в `config.yaml` и `.env`. «Озвучить текст» в обоих режимах отправляет текст прямо в TTS.
3. Для речи нажмите **Микрофон**, произнесите фразу и нажмите **Стоп**. Проверьте расшифровку и отправьте её. Начало захвата прерывает текущую речь аватара.
4. **Прервать** останавливает озвучивание. **Записать** начинает запись; повторное нажатие завершает её и открывает диалог сохранения MP4.

Редактирование текста остаётся доступным при ошибке микрофона. При потере WebRTC-сессии отправка и запись отключаются. Изменение Python, моделей, порта и TTS требует Stop/Start; параметры аватара и голоса используются при новом подключении.

## «Батя» как мозг аватара

В настройках выберите **Батя**. Приложение ищет checkout рядом с LiveTalking или в `~/batya` и предлагает его `.venv/bin/python`. Нужны подготовленное окружение Python 3.13 с зависимостями Batya, API-ключ Yandex AI Studio, folder ID и PostgreSQL с pgvector. Для локальной базы нужен работающий Docker Compose; приложение запускает только сервис `db` из `batya/compose.yaml`. Установка зависимостей описана в README самого Batya.

Параметры из `.env` LiveTalking и Batya подхватываются автоматически. Ключ и URL внешней базы также можно ввести в интерфейсе: они передаются сервису через окружение. При доступном Linux keyring сохраняются зашифрованно, иначе действуют до закрытия приложения. Интерфейс сообщает, какой способ доступен; секреты не попадают в профиль, аргументы запуска или журнал. Для внешней базы выберите соответствующий режим и задайте `BATYA_DATABASE_URL`.

Если API уже запущен, приложение использует его. Для внешнего сервера выключите локальное управление и укажите URL. Сервер должен отвечать на `/health` и объявлять `speech_stream: 1` через `/api/v1/capabilities`; для этого нужен Batya с изменениями ветки `feat/livetalking-speech-stream`. Обычный API Batya сохраняет прежнее поведение.

При **Запустить** сначала готовится «Батя» и база, затем серверы речи и LiveTalking. **Остановить** и закрытие завершают принадлежащие приложению процессы и контейнер базы. Уже работающие API и база остаются работать; том PostgreSQL сохраняется.

Перед WebRTC выберите сохранённый разговор или создайте новый. Его ID сохраняется в профиле; переподключение и перезапуск восстанавливают историю. Внешний WebRTC-клиент может передать UUID как `batya_conversation_id` в `/offer`; без него разговор создаётся автоматически. Каждый запрос `chat` может передать стабильный `request_id` для повторной доставки без второго запроса к модели.

Ответ появляется постепенно и сразу разбивается на короткие фразы для TTS. Сначала «Батя» без озвучивания решает, нужны ли действия с памятью, затем выдаёт окончательный ответ потоком без инструментов. Это добавляет один запрос к модели перед первыми словами, зато предварительный текст с инструментами не попадает в речь. TTS работает параллельно с генерацией текста; короткий ответ может закончиться раньше появления первого звука из-за задержки синтеза.

**Прервать** очищает текущую речь и запрещает дальнейшую озвучку прерванного ответа. «Батя» завершает и сохраняет его; следующий запрос в том же разговоре ждёт завершения предыдущего. При ошибке доступны сообщение и повтор с тем же ID. В разделе **Память и документы** можно посмотреть память и явно загрузить текстовый документ. Загрузка книг и индексация автоматически не выполняются.

## Данные и диагностика

Профили находятся в Electron userData (обычно `~/.config/livetalking-desktop/profiles.json`). В профиль не записываются API-ключи. Повреждённый JSON сохраняется как `profiles.corrupt-*.json`, после чего мастер открывается с пустыми настройками.

Журнал запуска доступен в левой панели. Отдельные логи моделей остаются в `/tmp/livetalking-qwen-*`. Исходные записи сервера находятся в `LiveTalking/data/record`; диалог сохранения копирует выбранный MP4 в указанное место.

После запуска приложение продолжает проверять доступность LiveTalking и серверов речи. Ошибка отображается у соответствующего сервиса; после устранения причины можно повторить запуск. Повторные нажатия Stop используют одну процедуру остановки. Уже работающие внешние сервисы приложение не завершает.

## Проверки

```bash
npm test
npm run build
npm run smoke
```

Smoke-тест запускает локальный fixture и отдельные временные профили: настройка → Start → WebRTC session → текст → interrupt → Stop, запуск с повреждённым профилем, а также «Батя» → потоковый ответ → прерывание → история после переподключения и перезапуска → ошибка и повтор → возврат в прямой режим. Проверяются также создание аватара до настройки голоса, прогресс при закрытом диалоге, миниатюра/выбор после перезапуска и удаления исходника, переименование/поиск, ошибка/повтор, отмена/закрытие и смена модели после записи во время ответа «Бати». Модели и GPU ему не нужны. Скриншоты и журнал записываются в игнорируемый `test-results/`.

На текущей машине отдельно проверены холодный запуск моделей, реальное WebRTC-видео и аудио, echo, ответ LLM, прерывание, MP4 и WebAudio → Qwen ASR → озвучивание. Для проверки ASR использован виртуальный микрофон с русским WAV; физическое устройство нужно проверить своей фразой.

Интеграция Batya проверена с существующей локальной базой, настоящим API Yandex, Qwen TTS и WebRTC, включая сохранение разговора после перезапуска API и Electron. Тесты базы запускаются в отдельной временной PostgreSQL-базе; рабочая база сохраняется.
