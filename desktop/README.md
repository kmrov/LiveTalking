# LiveTalking Studio — Linux foundation

Electron-интерфейс для локального LiveTalking. Эта версия умеет проверять окружение, запускать Qwen ASR/TTS и LiveTalking, показывать аватара по WebRTC, отправлять текст в LLM или на озвучивание, распознавать микрофон, прерывать ответ и сохранять MP4.

## Запуск

Нужны Linux с графической сессией и Node.js 22 или новее:

```bash
cd LiveTalking/desktop
npm ci
npm start
```

Если npm запретил установочные скрипты зависимостей и Electron сообщает, что не установлен, один раз выполните:

```bash
node node_modules/electron/install.js
```

Приложение само находит родительский checkout LiveTalking. Для установленного приложения поиск рассчитан на папку `LiveTalking` рядом с исполняемым файлом; для AppImage используется расположение самого AppImage, а не временный mount. Выбор каталога вручную нужен только при другой структуре папок.

## Первый запуск

Мастер предлагает `.venv/bin/python` внутри LiveTalking, vLLM из соседнего `.venv` и vLLM-Omni из соседнего `.venv-omni`. Пути можно изменить. Python, CUDA и веса приложение не устанавливает.

Пример существующей структуры:

```text
live/
├── LiveTalking/
│   ├── desktop/
│   ├── .venv/bin/python
│   ├── models/
│   └── data/avatars/
├── .venv/bin/vllm
├── .venv-omni/bin/vllm
├── .hf-cache-qwen/hub/
└── cloning/
    ├── voice_reference_name.wav
    └── voice_reference_name.txt
```

Для Qwen нужны подготовленные `Qwen/Qwen3-ASR-0.6B` и `Qwen/Qwen3-TTS-12Hz-1.7B-Base`, vLLM и vLLM-Omni. Подготовьте отдельные окружения по [инструкции Qwen3-ASR](https://github.com/QwenLM/Qwen3-ASR#deployment-with-vllm) и [инструкции vLLM-Omni](https://docs.vllm.ai/projects/vllm-omni/en/latest/getting_started/quickstart/). Мастер ищет кеш моделей в `HF_HOME`, соседнем `.hf-cache-qwen` и стандартном Hugging Face cache; проверяет файлы конфигурации, веса и все части разделённых весов. Также проверяются веса выбранной модели аватара.

Готовый WAV и одноимённый TXT находятся автоматически в `LiveTalking/data/voices`, `LiveTalking/voices` или соседней папке `cloning`. В `cloning` используются файлы `voice_reference_*.wav`. Предлагается самый свежий образец; если их несколько, можно выбрать другой из списка. Расшифровка должна точно соответствовать записи. В этой версии профиль ссылается на исходный WAV: сохраняйте его на месте.

Выберите модель и ID подготовленного аватара из `data/avatars`. Для локального аватара нужен NVIDIA GPU даже при внешних ASR/TTS серверах. Внешний режим проверяет модели через `/v1/models` и не запускает vLLM.

Нажмите **Проверить**, исправьте указанные проблемы, затем **Запустить**. При запуске профиль сохраняется автоматически. После первого успешного запуска он открывается и запускается сам, если включено «Запускать при открытии». **Остановить** и закрытие приложения завершают только его собственные процессы. Совместимые сервисы, которые уже работали до запуска приложения, остаются работать.

## Разговор

1. Дождитесь состояния «Работает» и нажмите **Подключить WebRTC**.
2. Введите текст и выберите «Чат с LLM» или «Озвучить текст». LLM использует текущие настройки LiveTalking в `config.yaml` и `.env`.
3. Для речи нажмите **Микрофон**, произнесите фразу и нажмите **Стоп**. Проверьте расшифровку и отправьте её. Начало захвата прерывает текущую речь аватара.
4. **Прервать** останавливает озвучивание. **Записать** начинает запись; повторное нажатие завершает её и открывает диалог сохранения MP4.

Редактирование текста остаётся доступным при ошибке микрофона. При потере WebRTC-сессии отправка и запись отключаются. Изменение Python, моделей, порта и TTS требует Stop/Start; параметры аватара и голоса используются при новом подключении.

## Данные и диагностика

Профили находятся в Electron userData (обычно `~/.config/livetalking-desktop/profiles.json`). В профиль не записываются API-ключи. Повреждённый JSON сохраняется как `profiles.corrupt-*.json`, после чего мастер открывается с пустыми настройками.

Журнал запуска доступен в левой панели. Отдельные логи моделей остаются в `/tmp/livetalking-qwen-*`. Исходные записи сервера находятся в `LiveTalking/data/record`; диалог сохранения копирует выбранный MP4 в указанное место.

После запуска приложение продолжает проверять доступность LiveTalking и серверов речи. Ошибка отображается у соответствующего сервиса; после устранения причины можно повторить запуск. Повторные нажатия Stop используют одну процедуру остановки. Уже работающие внешние сервисы приложение не завершает.

## Проверки

```bash
npm test
npm run build
npm run smoke
```

Smoke-тест запускает локальный fixture и отдельные временные профили: настройка → Start → WebRTC session → текст → interrupt → Stop, затем запуск с повреждённым профилем. Модели и GPU ему не нужны. Скриншот и журнал записываются в игнорируемый `test-results/`.

На текущей машине отдельно проверены холодный запуск моделей, реальное WebRTC-видео и аудио, echo, ответ LLM, прерывание, MP4 и WebAudio → Qwen ASR → озвучивание. Для проверки ASR использован виртуальный микрофон с русским WAV; физическое устройство нужно проверить своей фразой.
