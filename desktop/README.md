# LiveTalking Studio — Linux

Electron-интерфейс для локального LiveTalking. Интерфейс LiveTalking Studio отображается на английском; названия кнопок и состояний ниже приведены так, как они показаны в приложении. Приложение проверяет окружение, запускает Qwen ASR/TTS, LiveTalking и «Батю», показывает аватара по WebRTC, озвучивает потоковые ответы, распознаёт микрофон, прерывает речь и сохраняет MP4. «Batya» ведёт постоянные разговоры и память в PostgreSQL.

## Запуск

Нужны Linux с графической сессией и Node.js 22 или новее:

```bash
cd LiveTalking/desktop
npm ci
npm start
```

Если npm запретил установочные скрипты зависимостей и Electron сообщает, что не установлен, один раз выполните:

```bash
node node_modules/electron/install.js
```

Приложение само находит родительский checkout LiveTalking. Для установленного приложения поиск рассчитан на папку `LiveTalking` рядом с исполняемым файлом; для AppImage используется расположение самого AppImage, а не временный mount. Выбор каталога вручную нужен только при другой структуре папок.

## Первый запуск

Мастер предлагает `.venv/bin/python` внутри LiveTalking, vLLM из соседнего `.venv` и vLLM-Omni из соседнего `.venv-omni`. Пути можно изменить. Python, CUDA и программные зависимости нужно установить заранее; недостающие веса Studio скачивает автоматически.

Пример существующей структуры:

```text
live/
├── LiveTalking/
│   ├── desktop/
│   ├── .venv/bin/python
│   ├── models/
│   └── data/avatars/
├── .venv/bin/vllm
├── .venv-omni/bin/vllm
├── .hf-cache-qwen/hub/
└── cloning/
    ├── voice_reference_name.wav
    └── voice_reference_name.txt
```

Для Qwen нужны `Qwen/Qwen3-ASR-0.6B` и `Qwen/Qwen3-TTS-12Hz-1.7B-Base`, vLLM и vLLM-Omni. Подготовьте отдельные окружения по [инструкции Qwen3-ASR](https://github.com/QwenLM/Qwen3-ASR#deployment-with-vllm) и [инструкции vLLM-Omni](https://docs.vllm.ai/projects/vllm-omni/en/latest/getting_started/quickstart/). При **Start** Studio скачивает недостающие веса выбранного аватара и, в локальном режиме речи, обе модели Qwen со всеми конфигурациями и токенизаторами. Внешний режим не скачивает Qwen. Кеш выбирается в порядке `HF_HUB_CACHE`, `HF_HOME/hub`, существующая соседняя `.hf-cache-qwen/hub`, стандартный Hugging Face cache с учётом `XDG_CACHE_HOME`. Проверяется активная ревизия `refs/main`, конфигурации, токенизаторы, веса и все части разделённых весов.

Загрузка показывает название модели, общий прогресс и объём. **Stop** отменяет загрузку; повторное **Start** использует уже готовые файлы и докачивает текущий. Полученные байты сохраняются в `.studio-model-<id>.part` рядом с моделью при отмене, обрыве сети и закрытии приложения. Сохранённая часть привязана к источнику, закреплённой ревизии, размеру и контрольной сумме; прогресс при повторе учитывает эти байты. Если сервер не поддерживает продолжение, загрузчик начинает файл заново. Повреждённые части с неверной итоговой контрольной суммой удаляются.

Каждый новый файл проверяется целиком по размеру и контрольной сумме и только затем становится доступным модели; `.part` никогда не считается готовой моделью. Докачивание требует места для оставшихся байтов. Источники и ревизии Hugging Face закреплены в `server/desktop-model-catalog.json`; существующие непустые модели сохраняются. При запуске моделей Studio включает offline-режим Hugging Face, чтобы сервисы использовали подготовленный кеш. Для первого скачивания нужен интернет и свободное место: Qwen ASR/TTS вместе занимают примерно 6,5 ГБ.

Готовый WAV и одноимённый TXT находятся автоматически в `LiveTalking/data/voices`, `LiveTalking/voices` или соседней папке `cloning`. В `cloning` используются файлы `voice_reference_*.wav`. Предлагается самый свежий образец; если их несколько, можно выбрать другой из списка. Расшифровка должна точно соответствовать записи. В этой версии профиль ссылается на исходный WAV: сохраняйте его на месте.

В блоке **Avatar** нажмите **Select** для готового аватара или **Create avatar** для фото/видео. Модель определяется выбранной карточкой; вводить ID вручную не требуется. Для локального аватара нужен NVIDIA GPU даже при внешних ASR/TTS серверах. Внешний режим проверяет модели через `/v1/models` и не запускает vLLM.

Нажмите **Check**, исправьте указанные проблемы, затем **Start**. При запуске профиль сохраняется автоматически. После первого успешного запуска он открывается и запускается сам, если включено «Start on launch». **Stop** и закрытие приложения завершают только его собственные процессы. Совместимые сервисы, которые уже работали до запуска приложения, остаются работать.

Во время запуска верхняя полоса показывает текущий этап, а строки сервисов — загрузку и прошедшее время; ожидающие этапы помечены «Queued». Это время ожидания, а не оценка оставшегося времени. На одном GPU локальная Qwen ASR загружается до Qwen TTS: одновременная инициализация приводила к нехватке памяти для KV-кеша. LiveTalking запускается после готовности обеих моделей. Холодная загрузка моделей в GPU может занимать минуты. JIT-кеши FlashInfer для ASR и TTS разделены: после первой компиляции каждый сервис использует свой готовый модуль вместо пересборки при переключении между Python-окружениями. Если задан `FLASHINFER_WORKSPACE_BASE`, Studio создаёт в нём отдельные `livetalking-studio/asr` и `livetalking-studio/tts`. Подсказка под кнопкой проекции объясняет, почему подключение пока недоступно. При следующем запуске Studio может использовать уже работающие совместимые сервисы.

Нижняя строка подсказывает следующий шаг: настроить и запустить профиль, включить превью или проекцию, затем начать разговор. Параметры окружения, голоса и собеседника сгруппированы в настройках.

Ширину панелей **Profile** и **Conversation** можно менять, перетаскивая вертикальные разделители рядом с областью аватара. Выбранные размеры сохраняются между запусками и подстраиваются под ширину окна. Для управления с клавиатуры выберите разделитель клавишей Tab и используйте стрелки влево/вправо; Shift увеличивает шаг.

## Создание и библиотека аватаров

**Create avatar** открывает выбор исходника, имени и модели. MuseTalk v15 поддерживает PNG/JPEG и видео MP4/MOV/MKV/AVI; Wav2Lip — видео этих форматов. Подготовленные Ultralight доступны для выбора. Для фото используйте хорошо видимое лицо; видео нормализуется до 25 кадров/с без звука. Дополнительные параметры кропа и маски находятся в раскрывающемся блоке.

Первого аватара можно создать до настройки голоса, ASR/TTS и «Бати». **Check** проверяет выбранное Python-окружение, CUDA, локальные веса и место на диске. При **Create** недостающие веса скачиваются автоматически: для MuseTalk — VAE, UNet v15, face parsing и детектор S3FD; для подготовки Wav2Lip — S3FD. Qwen при создании аватара не скачивается. Детектор ищется в `avatars/<model>/…/detection/sfd/s3fd.pth` или Torch Hub `checkpoints/s3fd-619a316812.pth`. Этап «Downloading models» показывает прогресс; **Cancel** останавливает worker и сохраняет текущую часть модели для докачивания. **Retry** использует готовые модели и продолжает прерванный файл. Python/CUDA и программные зависимости устанавливаются отдельно.

Подготовка показывает этап и прогресс. Закрытие диалога, в том числе Escape, оставляет её работать; кнопка **Show progress** возвращает к текущей задаче. **Cancel** завершает её собственный процесс. После ошибки/прерывания **Retry** использует сохранённую копию исходника, если копирование успело завершиться. Закрытие Studio отменяет текущую задачу; после аварийного выхода состояние восстанавливается как прерванное. Готовый результат публикуется только после проверки всех кадров.

При работающем профиле действия подписаны **Stop and create** или **Stop and select**. Сначала завершите запись MP4. После выбора или подготовки сервисы запускаются отдельной кнопкой **Start**. Смена аватара закрывает WebRTC и поток событий; «Batya» сохраняет незавершённый ответ, который доступен в истории того же разговора.

Библиотека показывает существующие и созданные аватары по имени и миниатюре. Есть поиск и переименование без изменения ID; одинаковые имена допустимы. Неполные/повреждённые каталоги показываются с причиной и недоступны для выбора. Выбор сохраняется в текущем профиле вместе с настройками голоса.

Миниатюры обрабатываются отдельным Python-процессом: слишком большие изображения (более 32 мегапикселей), повреждённое превью или недоступный интерпретатор оставляют карточку без картинки. Недоступный сохранённый checkout открывает настройки с ошибкой библиотеки, чтобы можно было выбрать другой путь. Эквивалентные пути, включая ссылку на checkout, используют одну библиотеку и состояние задачи.

Уже запущенный внешний LiveTalking должен сообщать модель и канонический каталог через `/api/desktop/health`; Studio проверяет их вместе с мозгом. При несовпадении выберите другой порт или самостоятельно перезапустите внешний сервис. Studio его не завершает. После обновления кода ранее запущенному серверу может потребоваться перезапуск для нового health-ответа.

Готовые аватары остаются в `LiveTalking/data/avatars/<id>`. Созданный аватар хранит `studio-avatar.json`, миниатюру и собственный исходник в `source/input.<extension>`: первоначальный файл после успеха можно удалить. Рабочие задания, копии для повтора и журнал находятся в `data/.studio-avatar-work/<jobId>` и не отображаются карточками. Голос настраивается отдельно; его исходный WAV пока нужно сохранять на месте.

## Разговор

1. Дождитесь состояния «Running» и нажмите **Enable preview**.
2. Введите текст и выберите «Chat with LLM» или «Speak text». В режиме «Batya» все запросы `chat` к LiveTalking, включая внешние клиенты, проходят через него. В прямом режиме LLM использует настройки LiveTalking в `config.yaml` и `.env`. «Speak text» в обоих режимах отправляет текст прямо в TTS.
3. Для речи нажмите **Microphone**, произнесите фразу и нажмите **Stop**. Проверьте расшифровку и отправьте её. Начало захвата прерывает текущую речь аватара.
4. **Interrupt** останавливает озвучивание. **Record MP4** начинает запись; повторное нажатие завершает её и открывает диалог сохранения MP4. Перед отключением превью или остановкой профиля нужно завершить запись; во время смены разговора запись недоступна.

Редактирование текста остаётся доступным при ошибке микрофона. При потере WebRTC-сессии отправка и запись отключаются. Изменение Python, моделей, порта и TTS требует Stop/Start; параметры аватара и голоса используются при новом подключении.

Для разговора без кнопок подключите предпросмотр или проекцию и нажмите **Auto conversation**. Studio оставляет микрофон открытым, определяет фразу по голосу и после примерно 0,9 секунды тишины отправляет её в Qwen ASR, а распознанный текст — в режим «Chat with LLM» активного аватара. После ответа аватара слушание возобновляется. Под строкой состояния показывается уровень входящего звука: «waiting for signal» означает, что аудиоданные ещё не поступили; постоянно низкий уровень при речи подсказывает проверить усиление микрофона. Кнопка **Stop auto conversation**, Stop профиля или отключение аватара освобождают микрофон. Ручной режим **Microphone** остаётся доступен отдельно.

Пока аватар отвечает, автодиалог обычно не распознаёт новую фразу: так звук TTS из колонок не запускает следующий запрос. Флажок **Allow interruption** включает распознавание во время ответа и прерывает озвучивание при новой фразе. Используйте его с наушниками или после проверки эхоподавления на месте показа: при громких колонках возможны ложные срабатывания. Распознавание зависит от уровня речи и фонового шума; перед показом проверьте паузу и микрофон в реальном помещении.

## Проекция через Head in Jar

1. Подключите проектор как отдельный дисплей. В Head in Jar откройте проект с OBJ головы, выберите **Live video · WebRTC** и в **Connection access** укажите интерфейс своей локальной сети. Запустите сервер подключения. На Linux для поиска через mDNS должны работать Avahi и его daemon.
2. В Studio выберите аватар и разговор с Батей, запустите профиль и в блоке **Head in Jar** выберите найденный экземпляр. Studio подставит WHIP URL и очистит токен. Нажмите **Connect projection** и дождитесь статуса **Stream connected**. Поиск обновляется автоматически примерно раз в 15 секунд; Head in Jar на том же компьютере находится и без Avahi. По умолчанию клиенты выбранной подсети подключаются без токена. Если в Head in Jar включено **Require token**, Studio покажет это у найденного экземпляра: скопируйте Bearer token в Head in Jar и вставьте его в Studio в разделе **Advanced · token** перед подключением. Сам токен не публикуется через mDNS и не сохраняется в профиле. Для подключения на той же машине выберите **This computer** в Head in Jar; Studio найдёт его через локальную проверку даже без Avahi. Настройка **Require token** действует и для этого режима.
3. Проверьте живой кадр в Head in Jar, выберите проектор и нажмите **Start projection**. При смене разрешения дисплея проверьте физическую калибровку заново. Studio не включает проектор автоматически.
4. Говорите через микрофон Studio: после **Stop** проверьте распознанный текст и отправьте его. Чат, озвучивание текста, прерывание и запись направляются в проецируемый сеанс. Предпросмотр WebRTC Studio используется отдельно; перед переключением между ним и проекцией отключите текущее подключение.

При потере WHIP-потока Studio перестаёт отправлять в него реплики; выберите найденный Head in Jar повторно либо вставьте новый токен для ручного режима. **Stop** и закрытие Studio разрывают только WHIP-сеанс, запущенный этим окном. Сохранённый разговор Бати остаётся доступен после переподключения. Head in Jar выводит звук полученного WebRTC-потока через выбранное системное аудиоустройство; перед показом проверьте акустику отдельно.

## «Batya» как мозг аватара

В настройках выберите **Batya**. Приложение ищет checkout рядом с LiveTalking или в `~/batya` и предлагает его `.venv/bin/python`. Нужны подготовленное окружение Python 3.13 с зависимостями Batya, API-ключ Yandex AI Studio, folder ID и PostgreSQL с pgvector. Для локальной базы нужен работающий Docker Compose; приложение запускает только сервис `db` из `batya/compose.yaml`. Установка зависимостей описана в README самого Batya.

Параметры из `.env` LiveTalking и Batya подхватываются автоматически. Ключ и URL внешней базы также можно ввести в интерфейсе: они передаются сервису через окружение. При доступном Linux keyring сохраняются зашифрованно, иначе действуют до закрытия приложения. Интерфейс сообщает, какой способ доступен; секреты не попадают в профиль, аргументы запуска или журнал. Для внешней базы выберите соответствующий режим и задайте `BATYA_DATABASE_URL`. Голосовая модель по умолчанию — Qwen3.6 35B; для сравнения можно задать в `.env` Batya `BATYA_SPEECH_MODEL=aliceai-llm-flash` или `BATYA_SPEECH_MODEL=deepseek-v4-flash`.

Если API уже запущен, приложение использует его. Для внешнего сервера выключите локальное управление и укажите URL. Сервер должен отвечать на `/health` и объявлять `speech_stream: 1` через `/api/v1/capabilities`; для этого нужен Batya с изменениями ветки `feat/livetalking-speech-stream`. Обычный API Batya сохраняет прежнее поведение.

При **Start** сначала готовится «Batya» и база, затем серверы речи и LiveTalking. **Stop** и закрытие завершают принадлежащие приложению процессы и контейнер базы. Уже работающие API и база остаются работать; том PostgreSQL сохраняется.

Перед WebRTC выберите сохранённый разговор или создайте новый. Его ID сохраняется в профиле; переподключение и перезапуск восстанавливают историю. Кнопка **New** и выбор другого разговора переключают «Батю» без отключения WebRTC или проекции. Текущая озвучка останавливается, а прежний ответ завершается и сохраняется в старом разговоре. Во время записи MP4 смена разговора недоступна. Внешний WebRTC-клиент может передать UUID как `batya_conversation_id` в `/offer`; без него разговор создаётся автоматически. Для смены разговора у действующего сеанса доступен `POST /api/brain/session` с `sessionid` и `conversation_id`. Каждый запрос `chat` может передать стабильный `request_id` для повторной доставки без второго запроса к модели.

Ответ появляется постепенно и сразу разбивается на короткие фразы для TTS. После поиска контекста «Batya» запускает ответ и проверку необходимости сохранить личный факт параллельно. Первые слова больше не ждут проверку памяти; перед окончательным `done` запись памяти завершается. Ответ выдаётся потоком без инструментов, поэтому служебный текст не попадает в речь. TTS работает параллельно с генерацией текста; короткий ответ может закончиться раньше появления первого звука из-за задержки синтеза. В журнале «Бати» строки `batya_latency` показывают время поиска, первого текста и завершения.

**Interrupt** очищает текущую речь и запрещает дальнейшую озвучку прерванного ответа. «Batya» завершает и сохраняет его; следующий запрос в том же разговоре ждёт завершения предыдущего. При ошибке доступны сообщение и повтор с тем же ID. В разделе **Batya memory and documents** можно посмотреть память и явно загрузить текстовый документ. Загрузка книг и индексация автоматически не выполняются.

## Данные и диагностика

Профили находятся в Electron userData (обычно `~/.config/livetalking-desktop/profiles.json`). В профиль не записываются API-ключи. Повреждённый JSON сохраняется как `profiles.corrupt-*.json`, после чего мастер открывается с пустыми настройками.

Журнал запуска доступен в левой панели. Отдельные логи моделей остаются в `/tmp/livetalking-qwen-*`. Исходные записи сервера находятся в `LiveTalking/data/record`; диалог сохранения копирует выбранный MP4 в указанное место.

После запуска приложение продолжает проверять доступность LiveTalking и серверов речи. Ошибка отображается у соответствующего сервиса; после устранения причины можно повторить запуск. Повторные нажатия Stop используют одну процедуру остановки. Уже работающие внешние сервисы приложение не завершает.

## Проверки

```bash
npm test
npm run build
npm run smoke
npm run smoke:ui
```

Smoke-тест запускает локальный fixture и отдельные временные профили: настройка → Start → WebRTC session → текст → interrupt → Stop, автодиалог → ASR → автоматическая отправка в чат, подключение проекции → реплика в WHIP-сеанс → обрыв/повтор, а также «Batya» → потоковый ответ → прерывание → история после переподключения и перезапуска → ошибка и повтор → возврат в прямой режим. Проверяются также создание аватара до настройки голоса, прогресс при закрытом диалоге, миниатюра/выбор после перезапуска и удаления исходника, переименование/поиск, ошибка/повтор, отмена/закрытие и смена модели после записи во время ответа «Бати». Модели и GPU ему не нужны. Скриншоты и журнал записываются в игнорируемый `test-results/`.

`npm run smoke:ui` проверяет изменение ширины обеих панелей, сохранение размеров, работу в узком окне, защиту записи при отключении превью, обновление списка разговоров во время ответа, повторное нажатие «New», отмену распознавания при смене разговора и сохранение нового черновика во время отправки. Использует временный профиль и fixture; скриншоты находятся в `test-results/ui-audit/`.

На текущей машине отдельно проверены холодный запуск моделей, реальное WebRTC-видео и аудио, echo, ответ LLM, прерывание, MP4 и WebAudio → Qwen ASR → озвучивание. Для проверки ASR использован виртуальный микрофон с русским WAV; физическое устройство нужно проверить своей фразой.

Интеграция Batya проверена с существующей локальной базой, настоящим API Yandex, Qwen TTS и WebRTC, включая сохранение разговора после перезапуска API и Electron. Тесты базы запускаются в отдельной временной PostgreSQL-базе; рабочая база сохраняется.
